# 优化需求：验收与回归用例

本集针对需求中“拒绝/异常重试约束、手动单客户跑批”和技术方案中的“`renew_credit_customer_batch` 调用批次 Code”设计。它们应在优化实现合入后执行。

| ID | 优先级 | 场景与前置 | 执行 | 预期结果 |
| --- | --- | --- | --- | --- |
| RC-O-01 | P0 | 首次模型通过 | 后续连续触发跑批 | 33 个月内不再查询征信/朴道、不创建新的批次调用记录 |
| RC-O-02 | P0 | 首次模型拒绝，合同未到期 | 首次后 29 天、30 天分别跑批 | 29 天不查；第 30 天可查第 2 次；征信与朴道调用计数均准确 |
| RC-O-03 | P0 | 连续模型拒绝 | 每 30 天跑一次直到第 3 次 | 第 3 次拒绝后为模型拒绝终态；后续自动任务不再查征信/朴道、不再建批次记录 |
| RC-O-04 | P0 | 第 1 或第 2 次拒绝后模型通过 | 在允许的 30 天重试点跑批 | 立即为模型成功终态；后续自动任务不执行 |
| RC-O-05 | P0 | 首次模型异常 | 连续三天跑批 | 第 1、2 天允许重试；第 3 次异常后为模型异常终态；第 4 天不再自动执行 |
| RC-O-06 | P0 | 第 1 或第 2 次异常后返回通过/拒绝 | 在连续重试中执行 | 通过为成功终态；拒绝为拒绝终态；两者均停止后续自动重试 |
| RC-O-07 | P0 | 合同到期前已拒绝/异常终态 | 到期日后继续触发任务 | 不再自动查询外部数据或模型；计数不增加 |
| RC-O-08 | P0 | 模型拒绝/异常均为 3 次，且客户处于终态 | 调用单客户手动重跑接口 | 使用有效密钥时允许执行，次数不受限；创建新的调用批次，结果正确回写 |
| RC-O-09 | P0 | 同 RC-O-08 | 缺少、错误或过期密钥调用手动接口 | 返回认证/授权失败；不查询征信、不创建批次记录、不改客户状态 |
| RC-O-10 | P1 | 客户不是模型拒绝/异常终态，例如模型通过或准入拒绝 | 调用手动接口 | 被拒绝；接口只接受定义的两类状态 |
| RC-O-11 | P0 | 同一续授信客户连续三次模型调用 | 每次调用模型前查询数据库 | 每次插入一条 `renew_credit_customer_batch`；Code 唯一；均关联同一 `renew_credit_customer`；批次日期正确 |
| RC-O-12 | P0 | 触发 M01、M02、M03、M05 的一次调用 | 比对模型记录和结果表 | `model_record.code`、综合模型 `loan_model_result.code` 均为本次 batch Code，而非客户主表 Code |
| RC-O-13 | P0 | 返回通过、拒绝、异常、审批中各一次 | 调用后查两张表 | `renew_credit_customer_batch` 的结果、描述、时间与客户表本次处理结果一致；不得覆盖旧批次的历史结果 |
| RC-O-14 | P1 | 两客户、同一日期、并发触发；同客户重复点击手动接口 | 并发执行 | 每个实际调用独立 Code；同客户的并发策略明确（互斥或幂等），不会产生同 Code 双记录或错关联 |
| RC-O-15 | P1 | 历史单 Code 客户记录 | 完成优化发布后的首次任务 | 历史数据兼容可查询；没有 batch 记录时不误判为 0 次或无限重试；迁移策略可审计 |

## 优化版核心 SQL 断言

```sql
-- 每次模型调用必须有唯一批次 Code；表字段名以最终 DDL 为准。
SELECT code, COUNT(*)
FROM renew_credit_customer_batch
GROUP BY code
HAVING COUNT(*) > 1;

-- 同一客户的模型记录必须使用其关联批次 Code。
SELECT mr.id, mr.code, rccb.renew_credit_customer_id
FROM model_record mr
LEFT JOIN renew_credit_customer_batch rccb ON rccb.code = mr.code
WHERE mr.model_code IN ('M01', 'M02', 'M03', 'M05')
  AND rccb.id IS NULL;
```

## 需在开发前确认的契约

- 手动单客户接口的路径、请求参数、密钥 Header 名称、密钥轮换策略及审计字段。
- “3 次”的口径：包含首次调用，且拒绝按自然日 +30 天、异常按连续自然日；本用例按该口径设计。
- 外部征信与朴道的“实际查询”计数来源：调用日志、桩服务或持久化记录三者必须至少有一个可断言。
- `renew_credit_customer_batch` 的主键、关联外键、批次日期、状态/描述/次数字段及历史数据迁移规则。
